# Connect to your VPS (replace with your actual IP)

# Install Docker in one command

D
Your First Target

Add your authorized program to scope

🔒
Legal requirement — read this first
Only add programs you are actively enrolled in on HackerOne, Bugcrowd, or Intigriti. Never scan a target you don't have written authorization for. BugFlow's scope enforcer will block out-of-scope hosts, but you must configure it correctly first.

Open the scope file:

VPS 
nano config/scope/manual_scope.yaml

Replace the entire contents with your real program. Here is a filled example:

config/scope/manual_scope.yaml — real example 
# LEGAL USE ONLY — Only programs you are authorized to test

programs:
  - name: "YourProgramName"              # e.g. "Acme Corp"
    platform: "hackerone"                # hackerone | bugcrowd | intigriti
    program_id: "acme"                    # H1 program handle from the URL
    active: true                       # ← THIS MUST BE true to enable

    in_scope:
      domains:
        - "*.acme.com"                  # wildcard covers all subdomains
        - "acme.com"                     # root domain
        - "*.api.acme.com"               # nested wildcard (if in scope)
      ip_ranges: []                    # add CIDR ranges if program includes them
      urls: []

    out_of_scope:
      domains:
        - "blog.acme.com"               # check program policy for exclusions
        - "status.acme.com"
        - "careers.acme.com"
      paths:
        - "/logout"
        - "/signout"
        - "/delete-account"

    notes: "Added 2026-04-28. First target."
1
Find your program handle
Go to your H1 program page. The handle is in the URL: hackerone.com/programs/handle. Use that exact string as program_id.
2
Copy the in-scope domains exactly
Go to the program's Scope tab on H1. Copy every domain listed as in-scope. Use *.domain.com for wildcard entries.
3
Add all out-of-scope domains
Check the Out of Scope section on H1. Add every domain listed there. BugFlow's scope enforcer will never touch these hosts.
4
Set active: true
This is the switch that enables scanning. Leave it false for any program you're not ready to scan yet. You can have multiple programs — only active ones run.

Save and exit: Ctrl+X → Y → Enter

E
Launch

Build and start everything

VPS — from /opt/bugflow-elite/ 
docker compose up -d --build
⏱
This takes 10–20 minutes on first run
Docker builds the image with all Go tools (~5 min), then Ollama downloads the AI models llama3.2-vision:11b and qwen2.5-coder:14b (~7GB total, ~15 min). Only happens once — restarts are instant after this.

Watch it start up:

VPS — watch logs 
docker compose logs -f

Wait until you see these lines — that means everything is ready:

G
Manual Scan

Trigger a scan immediately

The scheduler runs automatically (incremental every 6h, full every 24h). To start a scan right now without waiting:

VPS — run incremental scan now (fast, ~15 min) 
docker compose exec bugflow python3 main.py acme.com incremental
VPS — run full scan now (all 9 stages, 1–2 hours) 
docker compose exec bugflow python3 main.py acme.com full
⚠
Replace acme.com with your actual target domain
The scope enforcer will block the scan if the domain is not in your manual_scope.yaml with active: true. This is intentional — it protects you.

from db.models import get_conn
conn = get_conn('./db/bugflow.db')
r = conn.execute(\"SELECT COALESCE(SUM(estimated_usd),0) FROM ai_costs WHERE DATE(timestamp)=DATE('now')\").fetchone()

# Restart after changing config or scope
docker compose restart bugflow-elite

# Stop everything
docker compose down

# Start again
docker compose up -d

# Run tests inside container
